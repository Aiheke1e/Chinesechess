# Chinesechess —— JJ 象棋屏幕识别与自动对弈实验

一个**屏幕感知型**中国象棋自动对弈程序：截取 JJ 象棋客户端画面 → 识别棋盘
→ AI 选招 → 自动落子，完全在外部进行（不改内存、不注入、不逆向）。

## 工作原理

```
┌────────────┐   ┌──────────┐   ┌────────┐   ┌──────────┐
│ JJ 象棋窗口 │──>│ 屏幕捕获 │──>│ 棋子识别│──>│ 棋盘状态 │
└────────────┘   └──────────┘   └────────┘   └────┬─────┘
                                                    │
                                           ┌────────▼────────┐
                                           │ Pikafish 引擎    │
                                           │ (UCI + NNUE)      │
                                           └────────┬────────┘
                                                    │ 走法
                                           ┌────────▼────────┐
                                           │ 自动落子(鼠标)   │
                                           └─────────────────┘
```

三模块解耦：
- `board.py`  —— 象棋规则状态机（走法生成 / 合法性 / 评估 / FEN）
- `pikafish.py` —— 唯一走棋引擎；负责 Pikafish UCI 通信、超时和进程清理
- `vision.py` —— Win32 窗口截图、棋盘几何检测、模板匹配识别（可换 YOLO 检测器）
- `play.py`   —— 人类化鼠标拖拽落子 + 主控循环
- `main.py`   —— 串起整条的入口
- `calibrate.py` —— 在真实客户端上标定几何、生成模板
- `simulator.py` / `verify.py` —— 无客户端时端到端验证（已通过）

## 识别方案（两种）

1. **零依赖模板匹配**（默认）：用 `calibrate.py --templates` 截 14 类棋子图当模板，
   每个交叉点做 `matchTemplate` 比对。优点：无需训练、即开即用；缺点：对界面缩放/
   换肤敏感。
2. **深度学习检测器**（可选）：`config.json` 设 `"use_detector": true`，用
   `YOLODetector` 接 ultralytics YOLOv8（检测棋子 bbox + 类别映射到 14 类）。
   优点：旋转/缩放/部分遮挡鲁棒；缺点：需标注训练数据。

## 当前推荐入口（ADB 模拟器）

项目目前实际使用的是 `control_panel.py` / `player.py`。它连接已经启动的安卓模拟器，支持红方或黑方在下方，并使用 `adb_geom.json` 保存当前棋盘几何。

最方便的启动方式是双击 `start.cmd`。首次使用时：

> 换电脑、重新下载或需要补齐 Pikafish/ADB 时，请先看 [运行文件清单](运行文件清单.md)，里面有直接下载链接、放置路径和完整启动步骤。

1. 在 JJ 象棋中打开标准初始棋盘。
2. 点击“自动标定”。换分辨率、缩放或皮肤后也要重新标定。
3. 保持“只读检查（不点击）”勾选，点击“运行一手”，核对识别的 FEN 和建议走法。
4. 核对无误后取消只读，点击“运行一手”做一次真实落子测试。
5. 确认落子成功，再点“开始自动”。“安全停止”会让当前操作收尾后退出。

### 桌面一键助手

桌面快捷方式“JJ象棋一键助手”会通过 `assistant_bootstrap.py` 启动控制面板：

1. 自动启动雷电模拟器（如果尚未启动）。
2. 自动打开 JJ 象棋（如果当前不是 JJ）。
3. 等待用户进入标准新棋或结构合法的残局；大厅和结算页不会触发点击。
4. 连续两次确认同一棋盘后，自动关闭只读模式并启动对弈。残局可在控制面板选择当前轮到红方或黑方；“自动判断”不唯一时默认红方。

模拟器路径和 JJ 包名可在 `assistant_config.json` 中修改。需要终止时点击控制面板的“安全停止”。
启动器会阻止重复运行，并把启动异常记录到 `work/assistant.log`；控制面板运行日志位于 `work/control_panel.log`。

### 直播讲解与弹幕互动

桌面控制台已经合并为左右双栏：左侧显示象棋走法、Pikafish 局势分析和实际点击指令，右侧显示抖音弹幕、进场、礼物、模型回复与语音状态。不包含数字人或视频生成。

- 引擎分析会给每步计算“讲解重要度”：普通走子只记录不朗读，吃重子、局势翻转、杀棋和收官才会主动解说。讲解任务与棋盘点击并行，不阻塞落子。
- 主播台可选“安静 / 自然 / 热闹”三档解说密度。默认“自然”：连续安静或数个普通回合后，只在等棋空档补充一段局面思路；新局面出现会丢弃过时解说。
- “游戏内沙盘”复用 Pikafish 已经算出的主变化，不发起第二次引擎搜索。吃掉车、马、炮大子，或深度达标的杀势置信度超过 80% 时，会在我方真实落子确认后点击 JJ 自带的“沙盘”，在游戏棋盘中演示后续 3–4 步并同步解说。主对弈识别在演示期间暂停，演示和回看总时长限制在约 8 秒内；退出后必须确认已经回到原实战局面或只发生了一手合法回应，才会恢复自动对弈。入口、复制局面或退出验证任一失败都会跳过或安全暂停，沙盘点击不会混入真实棋局。
- 直播解说和战术沙盘默认开启（TTS 仍由“开播语音”单独控制）。沙盘计分实测平均约 0.01 ms，动画使用 Tk `after` 分帧调度，语言模型和 TTS 使用后台线程；自动对弈运行在独立子进程，Windows 下设为略高优先级，确保引擎、识别和 ADB 不等待解说或动画。
- 语言模型通过智谱 OpenAI 兼容接口生成简短、可朗读的话术。密钥使用当前 Windows 账户的 DPAPI 加密，不写入项目源码和日志。
- 语音使用已有百炼云端 TTS，当前可切换 `Maia` 女声与 `longanyang` 男声。
- 弹幕默认只有以“问主播”开头才会回复；留空前缀可回复全部弹幕。
- 首次进场欢迎带频率限制；礼物连击会在短暂合并后只答谢一次，礼物优先于普通弹幕。
- “测试弹幕”“测试礼物”“播放自我介绍”无需真实观众即可检查整条语音链路。

直播配置保存在 `live_config.json`；互动事件日志位于 `work/live_events.jsonl`。抖音连接所需的外部连接器和独立运行环境位于 `D:\environment\shuzhiren`，不会把数字人依赖复制进象棋项目。

控制台采用清爽直播工作台布局：顶部显示模拟器、棋局、语音和直播互动四个状态卡；“开播体检”会在后台检查 ADB、JJ 前台状态、Pikafish、智谱密钥、百炼配置、音色与直播间设置，不会发送模型或 TTS 请求。对弈日志同时统计本次运行的识别告警、成功落子与完成对局数。
顶部可在“青瓷清风”、“深海极光”和“墨玉流金”三套主题之间实时切换，并可调整 72%~100% 的窗口透明度。界面会记住上次选择；主操作区只保留一键接管、停止和主播台，标定、单步、体检、故障截图等低频功能收入“更多工具”。

等待对方落子时采用最近三帧的棋盘占位多数结果。单帧高亮、移动动画或模板漏识别不会立即改变可信局面；只有连续画面与合法走法能够互相印证时，程序才会推进棋局状态。

正常对局还会优先使用“变化格快速识别”：将当前画面与上一张可信画面对比，只定位变化最大的交叉点，再由象棋规则从合法走法中反推唯一的起点和终点。候选走法仍须通过局部棋子复核和连续两帧确认，选中高亮不会被当成落子；无法唯一判断、全屏动画或弹窗出现时会自动退回完整90格识别。自己的落子确认同样先检查起点和终点，完整全盘识别作为异常兜底。

主控制台默认显示精简对局摘要，只保留走法、局势、确认耗时、识别告警和胜负结果。每一手棋以虚线分隔成独立区块，正式棋谱使用更大字号；红方走法用暖红色、黑方走法用高对比蓝色，等待和确认信息则弱化显示，扫一眼即可分清双方。引擎坐标、候选路线、点击坐标等技术信息仍完整记录在 `work/control_panel.log`，方便故障分析但不会挤满直播界面。

对弈子进程会持续写入 `work/runtime_status.json` 心跳，控制台可以区分“等待对方”、“引擎思考”和“落子确认”。心跳停滞时会自动截图；只有在没有未确认点击的安全阶段才会自动重建对弈进程，落子核对阶段不会盲目重试。控制台日志达到 2 MB 后自动轮换，棋局事件与直播事件达到 8 MB 后轮换，各保留最近两份历史。UI 只保留最新的必要行数，长时直播不会因文本无限累积而越来越卡。

点击“安全停止”时，程序会把最后一次确认过的 FEN、轮次、朝向和移动棋子位置保存到
`work/session_state.json`。再次点击“一键准备并等待新棋”或重新打开桌面助手，会优先核对并恢复该可信棋局；如果停止期间对方已经走了一步，也会在能唯一推导时自动补入后继续。

本局确认胜负后，程序会优先通过安卓文字节点查找“继续、再来一局、再来一盘、下一局、确定”；
若 JJ 使用纯游戏画布，则只在已确认胜负的前提下检测结算页下半部的大型绿色按钮。
它也会连续关闭“快速升级”“段位保护”等视频奖励弹窗，不会点击“领取”广告按钮。
点击成功后控制面板会重新进入等待状态，下一局棋盘出现后继续接管。

先做只读检查，不发送点击：

```powershell
py -3 player.py --once --dry --engine pikafish --movetime 500
```

只读模式永远只预览一手，不会点击棋盘。`initial_turn` 表示启动程序时该谁走；新开标准对局固定为 `r`，即便程序执黑也不要改成 `b`。

主控现在采用以下保护：

- 启动局面必须连续两帧一致，并通过棋子数量上限、双王和行棋合法性检查。
- 等待对手时只接受能由当前可信局面唯一推导出的合法一步。
- 落子前再次核对整个棋盘；一次走子只发送一组起点/终点点击。
- 点击后轮询确认完整的预期局面。确认失败立即停止，不重复点击。

当前 1920×1080 的 JJ 标准棋盘已经完成真实闭环验证：识别标准开局、红方落子、识别黑方回应、红方再次落子均成功。

每次运行还会追加写入 `work/events.jsonl`，包含 `position`、`move_selected`、`move_applied`、`opponent_move`、`end` 等事件。后续 TTS、走法讲解和直播弹幕模块可以直接消费这个 JSONL，不必侵入下棋主循环。

## 旧版 Windows 窗口入口

```bash
# 1. 安装依赖
pip install numpy opencv-python pillow pyautogui

# 2. (可选) 端到端自检: 用模拟棋盘验证识别+AI 闭环
python simulator.py
python verify.py
# 应输出: 识别 90/90 正确, AI 选招合法

# 3. 打开 JJ 象棋, 自动标定棋盘几何
python calibrate.py            # 自动检测; 失败用 python calibrate.py --manual 点四角

# 4. 生成棋子模板 (零依赖方案需要)
python calibrate.py --templates

# 5. 启动旧版 Windows 窗口流程
python main.py
```

## 象棋引擎

项目只使用随项目提供的 Pikafish，不再包含 Python Alpha-Beta 备用引擎。Pikafish
启动或计算失败时主控会安全停止并显示错误，不会悄悄切换到不同棋力的实现：

```json
{
  "engine_mode": "pikafish",
  "engine_path": "engine_bin/Pikafish-Windows-x86-64-universal.exe",
  "think_depth": 10
}
```

主控会把当前局面转成 FEN 发给 Pikafish，解析 `bestmove` 并通过合法走法校验后落子。

## 稳健性要点

- 用 `ctypes` 直接抓窗口 DC，减少全屏截图带来的坐标和多显示器问题。
- 落子支持分步拖拽（`play.click_drag`）。
- 轮次判定基于识别出的 `turn` 字段，避免抢拍/误触。
- 真实环境建议：先小范围人工核对 `calib_visual.png` 的交点是否对齐棋子中心；
  若界面缩放变化，重新跑 `calibrate.py`。

## 已知限制

- 当前几何/模板针对当前 JJ 棋盘皮肤与 1920×1080 模拟器；环境变化后必须重新运行“自动标定”。
- 模板方案对动态特效（选中高亮、最后一步标记）可能误判，可在 `extract_square`
  里加 mask 或改用检测器。
- 未处理“认输/和棋/网络断开”等弹窗；遇到无法推导的画面会超时停止。
- 不负责从 JJ 大厅自动匹配、报名或处理金币/奖励页面；请人工进入一盘新棋后再启动。
- 识别模板只适用于当前棋盘皮肤、分辨率和朝向；换肤、旋转棋盘或改变模拟器分辨率后必须重新标定。
- 正式长将、长捉与自然限着规则尚未实现。

## CCPD 大师棋谱开局库

直播解说可以使用 CCPD 大师棋谱识别开局定式。棋谱数据体积较大，不提交到
Git；首次使用执行：

```powershell
py -3 setup_opening_book.py
```

脚本会从
[Chinese Chess Practical Dataset](https://github.com/Yvonne761/Chinese-Chess-Practical-Dataset)
下载采用 CC BY 4.0 许可的数据，只提取开局变化和按开局分类的大师对局，生成
`data/opening_book.json.gz`。运行时优先匹配棋谱库，未安装或没有可靠匹配时自动
使用内置保守规则，不会影响自动落子。
